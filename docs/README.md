## 3. 文档规则（强制）

1. **单一事实来源层级**：`开发总纲.md` > `重构路线图.md` > 阶段文档 > 其他。下级文档不得与上级冲突；需要冲突时（例如阶段 4 想换渲染路线），**必须先更新上级文档并经用户确认**（走总纲第 9 章决策机制）。
2. **阶段完成必须回填**：每个阶段开发完成后，必须在该阶段文档末尾的「完成记录」章节填写：完成日期、改动文件清单、验收结果、遗留问题。未回填视为阶段未完成。
3. **状态跟踪表只改路线图**：阶段状态（⬜/🚧/✅）只在 `重构路线图.md` 的状态表中维护，各阶段文档内部的任务 checkbox 由开发过程勾选。
4. **代码改契约必须同步文档**：凡改动总纲 4.x 节的数据模型 / 接口，必须同步更新总纲对应表格。
5. 旧文档 `pdf-bilingual-reader-dev-guide.md`（原仓库根）与代码严重不符，已删除（2026-09-08 清理）；如需考古翻 git 历史。

## 4. AI 助手协作协议

与 AI 助手（CodeBuddy 等）协作开发本项目时：

1. **会话开局注入**：按第 2 节"新会话 AI 助手"顺序读取文档，无需重新审计代码。
2. **任务指派格式**：`"执行阶段 N 的任务 T-x"`（对应阶段文档中的任务编号）。
3. **阶段完成后**：AI 必须回填完成记录 + 勾选任务 checkbox + 更新路线图状态表，再汇报。
4. **决策升级**：AI 发现需要偏离阶段文档范围时，停下来询问用户，不得自行扩权（总纲第 7 章约束依然有效）。
5. 项目记忆：AI 工作日志位于 `.workbuddy/memory/`，跨会话延续。
6. **及时提交并推送**：有一定修改就及时 git 提交，**每个阶段性任务（阶段文档的
   T-x）开发完成并通过门禁后必须立即提交并 push 到远程**，再开始下一个任务
   （一个修复 / 一个小特性 / 一批环境适配 = 一个 commit），不跨会话积攒
   未提交改动（2026-09-16 教训：阶段12 全程 82 笔提交只存本地，远程零备份，
   磁盘故障即全丢）；消息规范见 `开发流程管理.md` §2。
7. **运行中的服务不可擅动**：重启后端、查杀端口进程、跑压测等影响运行中服务
   的操作，必须先确认用户当前没有正在使用应用（尤其翻译进行中）；用户开发期
   前端 dev 服务器常开，改 store/lib 模块会触发整页刷新丢会话——大宗改动前
   先告知（2026-09-11 压测误杀用户翻译事故的防复发约定）。
8. **打包需用户指令**：bug 修复后只提交代码并在 dev 验证，**不主动打包**；
   用户初步验收确认功能 OK 后再统一打包做装机验收（2026-09-13 约定——
   当日多次自行打包致用户反复重装）。
9. **信号源优先于规则补丁（防跑步机铁律，2026-09-14 用户定则）**：
   识别/提取/结构类问题**禁止**用文本正则、个案启发式、单篇特调修补——
   规则只对见过的形态负责，换个文件就倒退（v2→v18 跑步机与 2026-09-14
   结构重建层两度实证）。修法优先级：**换用训练过的模型信号源**（版面
   模型/视觉模型，对未见版式泛化）> 换技术栈 > 换架构 > 最后才是通用
   类级规则（须回答"对没见过的论文是否成立"并经多版式语料标定）。
   用户原话："技术栈不行就换技术栈、整体架构不行就换架构"。
