## 标题缺失根治记录（2026-09-12，text-layer-v17）

用户反馈库内 DALK 与新上传 FG-RAG 首页标题均未识别（系统性，非个例）。真机
复现定位双根因，与本次体检的「伪标题残留=0」并不矛盾——体检测的是"该降级
的没降级"，本次是反向缺陷"不该动的被动了"：

- **DALK**（EMNLP 版）：`_demote_sentence_headings` 的「≥14 词直接降级」
  误杀 17 词真标题。降级产物无终止符 → processor 续段合并把它当未完结段
  链式吞掉作者/摘要等后续块（首页粘成 1 块）；页眉剔除又按「与 doc_title
  相同」（降级块去强调符后与提取到的标题一致）把标题块整体吃掉——两级
  放大器叠加，标题彻底消失。
- **FG-RAG**（ACM 版）：`_split_glued_columns` 段尾截除规则把标题段误判为
  跨栏吸入片段——ACM 参考文献段合法含有标题全文，标题段尾窗在"其它段落"
  命中即被截空（原始 markdown 里标题完好，`# **Context-Aware …**`）。

**修复**（ocr/textlayer.py）：

1. 降级规则收窄：≥14 词需同时带句法证据（小写开头，或含小写句法证据词
   ——代词/系动词/情态动词/关系与指示词；学术标题内这些词几乎总大写，
   正文句子几乎总小写）；
2. 页 0 首个标题位置豁免（`protect_first`，句末标点规则仍适用）；
3. 拆分规则②段尾截除与③碎片段去重对 `#` 标题段豁免（标题去留交给粘连
   拆分与 processor 页眉剔除，后者本就豁免 `#` 前缀块）；
4. `TEXT_LAYER_MODEL` v16→v17 版本熔断：旧文本层缓存整体失效重建，
   翻译缓存按 text_hash 键控、未变化文本免重译。

**E2E 复验**：DALK p0 恢复 17 块（修复前 1 块）、FG-RAG p0 恢复 24 块，
两篇标题均为首个 `#` 块且 doc_title 提取正确；pytest 146/6、compileall 过。
人工验收：用户重新上传（或重新翻译）两篇后确认。

## 标题根治二期：证据分级架构（2026-09-12 晚）

用户质疑成立："每次都是针对不同文章特调"。复盘确认：此前的规则全部是对
pymupdf4llm 二手输出的字符串推理（词数/句法/重复），每条都从个案倒推、
只对见过的形态负责（≥14 词规则救了 GraphRAG-Bench 却杀了 DALK；段尾截除
救了 ACL 单位行却杀了 FG-RAG）。本次不再加文本规则，**换信号源**：

1. **几何证据（主）**：第 1 页字号最大、最靠上的连续行 = 标题——学术排版
   铁律，对没见过的版式同样成立。直接读 pymupdf span 字号/坐标
   （`ocr/title_detect.py`），支持两行大标题合并、小型大写混排拼接、
   竖排文字（arXiv 左缘印章）剔除、页脚带剔除；
2. **metadata 互证**：出版 PDF 内嵌 title 字段，归一化重叠时优先采用
   （出版者写入，与排版无关的独立信号）；
3. **页0标题块矫正**：证据认定的标题若在首页以纯文本块存在（历史误伤形态，
   如 LightRAG 全大写无 # 块），提升为 "# " heading——读者所见与证据一致；
4. 原文本启发式（两级优先级 + 降级/拆分规则）降为兜底，不再新增。

**真机验证**：用户论文目录 8 篇（Survey/DALK/FG-RAG/GraphRAG/HippoRAG
1&2/KAG/LightRAG）全链路 8/8 通过——doc_title 正确、页 0 首块均为标题；
合成 PDF 回归测试 4 例（几何判定/两行合并/metadata 优先/竖排剔除）。
已知长尾：小型大写字间空格重建不完美（ANDFAST），仅影响术语表提示词观感，
读者标题块取自原文块文本不受影响；后续以真实样本逐步校正间距阈值。
