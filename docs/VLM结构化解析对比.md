## 一、逐维度结论

### 1. 公式：决定性胜利（本报告最重要的数字）

- **B 共产出 40 段定界 LaTeX（7 种宏），A 全样本 0 段**——textlayer 路线把数学拍平成 Unicode 碎片（𝑥/◆/ⁱⁿⁱtⁱal），这是「公式总有点问题」的根源；B 在提取层直接给出结构化 LaTeX。
- 质量（人工目检）：DALK p5 四个编号展示公式完整正确（`\(p_{self} = \text{Template}_{\text{self}}(Q, G_Q, k).\) (1)` 等）；Attention p4 的招牌公式 `\[ \text{Attention}(Q, K, V) = \text{softmax}(\frac{QK^T}{\sqrt{d_k}}) V \]` 完全正确，行内 `\(d_k\)`/`\(\frac{1}{\sqrt{d_k}}\)` 全对；FG-RAG p3（ACM 重公式页）质量略毛糙但结构在。真值侧数学字体 span 共 167 个，B 捕获 40 段（span≠公式段，一段公式常含多个数学字体 span）。
- 现有 `formula_hint` 按需视觉重识别、`mathFragment.ts` 显示层启发式在新路线下退位为兜底。

### 2. 内容完整度：平均 0.9556 vs 0.9772，差距全部来自两个已定位个案

- **DALK p9（bag 0.687）：丢的是 Table 8**（COVID-QA 结果表，整表被模型丢弃，输出零表格标记）。注意 `pdf find_tables` 同样没检出这张无边框表——生产管线在这页也是失败的，只是失败方式不同（表格文本漏进正文成乱码段，A 的 bag 0.992 是「完整保留了乱码」）。
- **FG-RAG p3（bag 0.899）：丢的主要是页眉运行头**（"Context-Aware Fine-Grained Graph RAG … CIKM '25, November 10–14, 2025, Seoul…"）——这是生产管线用 `_RUNNING_HEAD`/`_FOOTER_PAT` 费劲剔除的噪音，**B 自己丢了它是净收益**。
- 剔除这两个可解释个案后：B 平均 bag ≈ **0.988** vs A ≈ 0.983，且**版式最复杂的首页/标题页 B 全面更高**（DALK p1 0.996 vs 0.976、FG-RAG p1 0.997 vs 0.960、FG-RAG p5 0.990 vs 0.969、Survey p1 0.995 vs 0.977、Attention p1 0.990 vs 0.973）——正是现行启发式补丁最吃力的页面类型。
- B 残留的页码噪音（"2191"/"2188" 独立成行）现有 `_NOISE_BLOCK` 过滤器直接处理。

### 3. 双栏阅读顺序：显著更好，但非 100%（诚实边界）

- 可度量的 5 个双栏页：B 得分 1.0×4 + 0.79，优于 A（1.0×3 + 0.667×2）。
- **反例（人工目检发现）**：DALK p2 物理版式为左栏（§1 尾+贡献 bullets，y 到 652）→右栏（§2 Related Work，y0=70），B 输出把右栏整栏排前（Related Work 在首、bullets 在尾）——**整栏交换**，内容完整（bag 0.995）但顺序错。A 在该页 sim 0.990 说明其输出贴近真值 y 序（自身列重排未触发），同样不是正确列序。
- 结论：B 的顺序是模型级能力，多数页正确；混合架构应保留 textlayer 现成的几何列检测（`_column_reading_order` 的块坐标逻辑）作为高置信双栏页的顺序强制/校验手段。

### 4. 表格：决定性短板，但有已被生产验证的出路

- B 全样本输出 **0 个表格标记**——hosted PaddleOCR-VL-1.5 在整页「OCR:」提示下直接丢弃表格。
- 补充实验（元素级识别）：对 DALK Table 8 区域裁剪后用「Table Recognition:」提示，输出为 `<ecel><fcel>` 伪标签乱码（裁剪含邻栏文字时更糟）——**元素级表格识别在当前 hosted 版不可用**。
- 出路：**维持 v5 用户决策（表格=快照图）**，且把快照区域在送 VLM 前打白遮罩（见补充实验 2），表格文本既不进译文也不产生乱码段。结构化表格转 markdown/HTML 列为远期，不进本阶段。

### 5. 截断与延迟

- 截断（finish_reason=length）**0/12 页**：max_tokens 8192 在这些版式下未触顶；脚本内置的按栏对半重发机制保留为长文档（书籍/超密页）兜底，未消耗验证。
- B 平均 **6.4s/页**（3.1–13.3s）vs A 本地约 0.5s/页：页级流式下首页约 7s 可见（现状约 1s，可感知但可接受）；缓存命中后 0。数百页电子书首跑会到分钟级——保留「纯文字页本地提取、图表公式密集页才走 VLM」的按需触发作为后续优化位。

### 6. 其他观察

- 图内文字/图标签会以正文形态漏出（Attention p4 的 "Scaled Dot-Product Attention" 标签）→ 由遮罩方案解决（下节实验 2）。
- 脚注偶发与正文合并（Attention p4 首跑脚注 4 被并成伪分式 `\frac{4}{...}`；遮罩重跑后消失）——低频、非破坏性，先观察不专项处理。

## 二、补充实验

1. **图区域打白遮罩后整页重解析（Attention p4）**：脚注伪分式消失、29 段行内公式保留；但图标签仍漏出——原因是标签文字在光栅图 bbox 之外（矢量绘图簇内）。结论：遮罩必须用生产现成的 `_figure_regions`（光栅+`cluster_drawings` 矢量簇+find_tables，含 `_MERGE_GAP` 合并），不能只用 `get_image_rects`。
2. **表格元素级识别（DALK Table 8）**：不可用（见维度 4），确认表格走快照。
3. **确定性**：两轮全样本重跑数值一致，结果可复现、缓存策略有效。

## 三、结论与建议

**判断：整页 VLM 结构化解析在公式（0→40 段 LaTeX）与复杂版式页内容完整度（+2~3 点 bag）上决定性优于现行 textlayer；阅读顺序显著更好但非 100%；表格是明确短板但生产已有快照机制兜底。建议以混合架构立项替换数字页的文本提取主路径：**

```
PyMuPDF 几何层（不动）：区域检测（_figure_regions）→ 图表快照 + 遮罩
                                                    ↓
VLM 解析层（新）  ：整页「OCR:」→ 文本段 + \(..\) LaTeX 公式（列序正确率为主，几何列检测兜底）
                                                    ↓
交叉校验层（新）  ：VLM 输出 vs 文本层真值 bag F1（快照区域文本从真值扣除）
                    → 低于阈值页自动回退现行 textlayer 管线（最坏=现状，内容完整兜底）
                                                    ↓
现有后续管线（不动）：噪音过滤/跨页合并/标题几何检测/翻译/缓存
```

- 免费卖点不受影响（PaddleOCR-VL 免费档、现有 Key/账户），延迟代价为首页 ~7s。
- 现行 ~10 层提取补丁中的列重排/伪标题/斜体上标/跨栏拆分等预期大部分可退役，退役清单在阶段开发中按回归数据逐项确认。
